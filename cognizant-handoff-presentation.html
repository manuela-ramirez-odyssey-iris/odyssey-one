00 · Summary

What we're proposing

We've built a production-grade frontend implementation of the Odyssey design system in React — 28 normalized components, design tokens, CSS, a Figma library, a visual contract, and the documentation behind every decision.

We're proposing a workflow where the design team delivers a running, validated prototype instead of static specs — and Cognizant AI-ports it to Angular instead of rebuilding visually from PDFs.

The design system stays the single source of truth for both sides. PrimeNG stays where it adds value. Visual interpretation — the part that breaks today — gets replaced by an executable contract.

08 · Component port example

The port is mechanical.

Our components are intentionally dumb: pure presentational, props in / events out. No global state, no effect chains, no React-specific gymnastics. With AI assistance, a component like this takes 15–30 minutes to port.

Button.jsx
React (today)
export default function Button({
  children, variant = 'primary',
  size = 'md', disabled = false,
  icon, iconRight, ...props
}) {
  const classes = ['btn',
    `btn--${variant}`,
    `btn--${size}`,
    icon && 'btn--has-icon'
  ].filter(Boolean).join(' ')

  return (
    <button className={classes}
      disabled={disabled} {...props}>
      {icon && (
        <span className="btn__icon">
          {icon}
        </span>
      )}
      {children}
      {iconRight && (
        <span className="btn__icon btn__icon--right">
          {iconRight}
        </span>
      )}
    </button>
  )
}
button.component.ts
Angular (the port)
@Component({
  selector: 'ody-button',
  standalone: true,
  template: `
    <button [class]="classes"
      [disabled]="disabled"
      (click)="clicked.emit($event)">
      <span class="btn__icon" *ngIf="icon">
        <ng-content select="[icon]"></ng-content>
      </span>
      <ng-content></ng-content>
      <span class="btn__icon btn__icon--right"
        *ngIf="iconRight">
        <ng-content select="[iconRight]"></ng-content>
      </span>
    </button>
  `,
})
export class ButtonComponent {
  @Input() variant = 'primary';
  @Input() size = 'md';
  @Input() disabled = false;
  @Input() icon = false;
  @Input() iconRight = false;
  @Output() clicked = new EventEmitter();
  get classes() { /* same as React */ }
}
=

Identical across both

All CSS classes (btn btn--primary btn--md), all design tokens, the rendered output — pixel-identical against the DesignSystemMap.

→

Mechanical changes

Function → class. Props → @Input. Callbacks → @Output events. JSX → Angular template. children → <ng-content>.

14 · The non-negotiable

The maintenance rule.

Rule

All UI changes originate in React + Figma. Then port to Angular. Never patch only-Angular.

If this rule slips, the design system drifts and we lose every benefit within 6 months. This is the single most important governance decision in the proposal — and it protects both teams equally.

It is also the rule that earns the political bargain: in exchange for accepting it, Cognizant gets a faster, more consistent frontend pipeline that doesn't depend on any one person.

15 · What we're asking for

To move this forward.

  1. Read access to your Angular repo. We need to understand version, state management, styling, PrimeNG patterns, and module conventions before we can scope the port precisely.
  2. A feature branch for a proof-of-concept port of 3–5 components — including one organism — running in your stack within the week.
  3. A 30-minute review session to walk through the proof and decide who carries the remaining components.
  4. The tech lead's name and time for the maintenance-rule conversation. Whoever owns long-term system integrity should sign off explicitly.
  5. Acceptance of the approval gate — once a feature is locked in React, no design changes without going back through the prototype.

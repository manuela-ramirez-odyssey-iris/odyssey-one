### Figma modelling: what a swap can and cannot do

- **An INSTANCE_SWAP cannot select a variant.** Its picker lists COMPONENTS. I spent two rounds trying to make one act as a badge-variant control, including a wrong guess that library publishing was the cause; the user's screenshot of the picker offering "Badge / Spinner / StopBadge" is what settled it. **Exposing the nested instance is Figma's only mechanism** for driving a nested variant from the parent panel — and it is all-or-nothing, so `Shape` / `Show dot` / both icon slots ride along beside `Variant`. That cost is real and now written into the master's description rather than left to be rediscovered.
- **A swap IS right when the alternatives are different components** — SubAccordion's expand-all offered ButtonLink vs Button. That one still failed as a control in the panel, so it became a plain `Show Secondary Button` BOOLEAN with its own instance: same action drawn two ways, used INSTEAD of one another. Lesson: in this file a boolean + a real instance beats a swap almost every time.
- **`StopBadge`'s `changed` inverts on purpose.** Completed/Issue put White on a saturated 600 fill; there is no Purple/600 primitive to sit beside Caribbean Green/600 and Bittersweet/600. Rather than propose a new primitive (a gated, brand-new token), the user chose the pale pair — `--purple-100` pill + `--purple-800` label — which is **already what the app means by a changed field** (`Badge variant="purple"`). Two consequences: the circle's ring is `--purple-800` not `--white` (on a pale pill only dark ink separates circle from pill), and the glyph is a **dot** (the ring leaves ~6px; a 24-grid lucide master turns to mush, and a dot implies neither good nor bad).

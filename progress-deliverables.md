### Refinement round — five user-reported fixes after first use

Real usage of D2's dev mode surfaced five gaps in one pass: default framework, nested-component blindness (the headline), a session-gate hole, a contrast miss, and a z-index fight with the detail modal. Commits: `d6ab8b3` (nesting), `fb518a0` (Angular default, session gate, dot contrast, overlay-yields-to-modal), `b4a8ef0` (DataTable demo bugfix found by dev mode itself).

- **Nested inspection (the headline).** Original overlay only labeled the outermost `@odyssey/ui` component — anything composed into a slot (e.g. a `DataTable` cell holding an `odyssey-action-menu`) was invisible, and slot composition is the common case, not the edge case. New model: hover walks the full component chain and labels the **innermost** component, with a clickable ancestor breadcrumb (`DataTable › odyssey-action-menu`) so either level is reachable. Ancestors render muted in their React name; the leaf renders in whichever framework the toggle has selected. Chain outlines are weighted by depth — leaf solid, ancestors progressively dashed/dimmed — so the nesting reads visually before you even click. New **All levels / Outermost** nesting option in the flyout, defaulting to All levels; chips for a nested chain stagger 14px per depth so they don't stack unreadably. Browser-measured against the live app: **141 chips at All levels vs. 18 at Outermost** on the same view — the old outermost-only mode was hiding 87% of what's on screen.
- **Angular is the default framework** (was React) — matches the audience: devs porting components read the Angular name first.
- **Activation moved to sessionStorage** so a fresh tab with no `?dev=1` shows nothing, while in-app navigation (React Router drops the query string) keeps dev mode on for that tab; preferences (mode/framework/corner/nesting) stay in localStorage, unaffected. See "harden the session gate" below — the read path is now filtered so a tampered or regressed localStorage blob can't reopen the gate on its own.
- **NORMALIZING dot contrast** raised — the in-progress status dot on chips was failing to read against the chip background at a glance.

### Harden the session-gate read path (post-refinement)

The write path already split `enabled`/`everActivated` into sessionStorage and everything else into localStorage, but the **read** path spread the entire parsed localStorage blob into state (`...prefs`) — so a localStorage entry carrying `enabled: true`/`everActivated: true` (hand-tampered, or written by any future regression in the write path) bypassed the session gate and rendered dev tools in a fresh tab with no `?dev=1`. Fixed in `apps/odyssey-one/src/devmode/useDevMode.js`'s `ensureInit()`: the localStorage blob is now filtered to drop session-owned keys (`enabled`, `everActivated`) before merging into state, no matter what the blob contains. Unknown non-session keys still round-trip unchanged — the filter is a blacklist against `SESSION_FIELDS`, not a whitelist of known preference names, so it doesn't disturb forward-compat with future preference fields. New test: seeded `localStorage['odyssey-devmode']` with `{enabled:true, everActivated:true, mode:'all'}` and empty sessionStorage, no URL param → `enabled`/`everActivated` both resolve false, `mode` still hydrates `'all'`. Full suite: 131 files / 1686 tests green.

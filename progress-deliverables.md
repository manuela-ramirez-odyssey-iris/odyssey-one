### The bug the browser caught and the tests could not

**Every route renders its own `AppShell`**, so rail state held there was re-initialised on each navigation — the hamburger silently forgot itself the moment you left the page. Only visible by driving the real app; no unit test was ever going to see it. Fixed with a `SidebarProvider` above the router alongside the existing providers. `useSidebar` **degrades to component-local state when no provider is present** rather than throwing, because `AppShell` is rendered bare in dozens of route tests and wrapping every one would be churn for no coverage — 79 tests failed on the throwing version before that call was made.

### Harden the session-gate read path (post-refinement)

The write path already split `enabled`/`everActivated` into sessionStorage and everything else into localStorage, but the **read** path spread the entire parsed localStorage blob into state (`...prefs`) — so a localStorage entry carrying `enabled: true`/`everActivated: true` (hand-tampered, or written by any future regression in the write path) bypassed the session gate and rendered dev tools in a fresh tab with no `?dev=1`. Fixed in `apps/odyssey-one/src/devmode/useDevMode.js`'s `ensureInit()`: the localStorage blob is now filtered to drop session-owned keys (`enabled`, `everActivated`) before merging into state, no matter what the blob contains. Unknown non-session keys still round-trip unchanged — the filter is a blacklist against `SESSION_FIELDS`, not a whitelist of known preference names, so it doesn't disturb forward-compat with future preference fields. New test: seeded `localStorage['odyssey-devmode']` with `{enabled:true, everActivated:true, mode:'all'}` and empty sessionStorage, no URL param → `enabled`/`everActivated` both resolve false, `mode` still hydrates `'all'`.

### ORD-02 — Every Orders row click opens the Order Summary (Draft detour removed)
**Decided:** 2026-07-07
**Previous state:** `OrdersRoute` row click branched on status: `Draft` rows navigated to `/orders/create?draft=<orderNumber>` (spec §4 / plan decision 17 — reopen a session draft in the create form); all other rows opened `/orders/<orderNumber>` (Order Summary). After the S80 data unification, the shared generator seeds `'Draft'` into the unshipped-order status pool (`tools/generate.mjs` `UNSHIPPED_STATUS_POOL`, weight 20/100 ≈ 110 rows), so those generated rows also hit the create-form branch — but `getDraft()` only knows session drafts, so the form opened blank. Users experienced "random" navigation: same click, sometimes summary, sometimes an empty create flow.
**Decision / Finding:** Row click **always** opens the Order Summary page — every row, Draft included (Manuela, 2026-07-07: "Every row should open order summary when clicked"). The `?draft=` reopen path in `CreateOrderForm` is retained as a documented dev trigger; nothing navigates to it from the grid anymore. Supersedes plan decision 17's row-click detour (draft reopen as a grid behavior); a future explicit "Edit" row action can restore form-editing for drafts.
**Rationale:** Uniform, predictable navigation; the summary page renders any order (session drafts at full fidelity via `getOrderView`). Companion fix: `getOrderList`'s mock merge now has overlay rows **shadow** base rows sharing an `orderNumber` (previously `[...overlay, ...base]` with no dedupe — a draft saved over a generated row would duplicate it and collide TanStack row ids).
**Source:** User bug report + repro (S80 wrap → S81 priority 0); root-cause trace this session (generator status pool → `OrdersRoute.jsx` status branch → `getDraft` miss).
**Affects:** `apps/odyssey-one/src/routes/orders/OrdersRoute.jsx` (onRowClick), `apps/odyssey-one/src/api/services/orderService.ts` (`getOrderList` overlay shadowing), `orderService.test.ts` (+1 shadow test). Stories: LINX-10233 (View Order — the row-click target), LINX-10248 (Edit Order — where draft-reopen semantics move next).

### ORD-04 — Per-tab columns, actions, sorting, standardized pagination, Export
**Decided:** 2026-07-27
**Previous state:** `OrdersRoute`'s single grid rendered ONE shared 10-column set across all three main tabs (All/Draft/Validation Errors) regardless of which tab was active — no header sorting, row selection checkboxes present, no per-row Submit/Cancel/Resolve actions, no Export, and pagination unstandardized (no fixed default/step).
**Decision / Finding:** Each main tab now renders its own Jira/Figma-specced column set (`ordersColumns.jsx` `TAB_COLUMNS`): All = 14 data columns + Action kebab (View/Edit/Submit/Cancel/Copy/Restore per row status) with Hazmat amber badges, Order Status badges, 3-line Shipper/Destination location cells, and `--`/blank empty rules; Draft = 5 columns + kebab (Edit/Submit/Cancel, with a confirm modal on Submit/Cancel); Validation Errors = 4 columns + a direct Resolve button (enabled only while `draftOrderStatus === 'Ready'`). Header sorting is server-driven (manualSorting, one column always drives, asc↔desc) with a per-tab default (All: orderNumber desc: Draft: lastEdit desc — inference, cheap to change; Validation Errors: errorCount desc). Row-selection checkboxes are REMOVED entirely (no bulk actions surface exists yet). The toolbar's Filters button stays disabled pending the global-search/filter-panel decision; a new Export button opens a `ModalMedium` confirm (shows row count + active tab name) and streams the current tab's shape to `.xlsx` via a dynamic `xlsx` import, capped at 25,000 rows (`EXPORT_ROW_CAP`). Pagination is standardized across ALL domains (Shipments included) to page sizes 10–40 in steps of 5, default 25 (LINX-8091's audit-trail default informed the step; the standardization itself is a cross-domain Paginator change, not Orders-only).
**Rationale:** Closes the ORD-01 conformance gap (LINX-9896 grid columns/actions, LINX-11165 Export) using the actual Jira ACs + Figma per-tab mocks instead of the old lean placeholder grid; checkboxes were dropped because no bulk-action story exists yet (PO feedback + S94 user call) — adding the selection column back is cheap once one lands; standardized pagination removes a long-standing Shipments/Orders inconsistency in one pass.
**Source:** LINX-11658 (All tab AC), LINX-11663 (Draft tab + Submit confirm copy), LINX-11659 (Validation Errors tab + Resolve gating) acceptance criteria; Figma nodes 4686-5238 (All), 4686-5812 (Draft), 4686-6176 (Validation Errors); S94 user decisions (checkboxes dropped, Filters halted pending the global-search decision, pagination standardized 10–40/25 per LINX-8091, Export = current-tab Excel with a 25k cap).
**Affects:** `apps/odyssey-one/src/components/orders/ordersColumns.jsx` (new per-tab `TAB_COLUMNS`), `OrdersTable.jsx` (tab-driven columns + Action/Resolve column, checkboxes removed), `OrdersRoute.jsx` (lifted sorting state, Submit/Cancel confirm modals, Export modal wiring), `OrdersToolbar.jsx` (Export button, Filters disabled, old direction-only sort toggle removed), `OrdersExportModal.jsx` (new), `api/types/orderRowVm.ts` + `api/mappers/mapOrderListRow.ts` (per-tab VM fields; dead-code swept: `origin`/`destination`/`earlyPickup`/`commodity` VM fields + their `formatPlace`/`formatDateTime` helpers removed — superseded by `shipperLocation`/`destinationLocation`/`latestPickup`/`latestDelivery`), `api/services/orderService.ts` (`SORT_GETTERS`, submit/cancel mutations), `tools/generate.mjs` (I10 invariant: createdAt/createdBy/lastEditAt/draftOrderStatus/errorCount on every order row), `packages/ui/src/Paginator.jsx` (standardized page-size options, all domains). Stories: LINX-11658, LINX-11663, LINX-11659, LINX-11165, LINX-8091 (pagination default reference), LINX-10233/10248/10258/10259 (row actions — now wired instead of stubs).
